# What is CAGE?

CAGE is a standalone, glyph-based systems language. Its surface is built primarily from emoji and grapheme sequences, but the important part is not the visual novelty: CAGE treats legality, authority, resource usage, failure and execution as part of the language.

A CAGE program does not become executable merely because it parses. V4 introduces a versioned Constitution, a sequence of compiler Courts, and a final Tribunal admission stage. Source begins presumed inadmissible and earns an execution certificate only after its declarations and proof evidence agree.

## The core idea

```text
DECLARE
  ↓
CONSTRAIN
  ↓
ACCOUNT
  ↓
PROVE
  ↓
PASS THE COURTS
  ↓
SURVIVE THE TRIBUNAL
  ↓
RECEIVE EXECUTION AUTHORITY
  ↓
RUN
```

CAGE is intentionally not forgiving. It does not silently widen types, invent missing capabilities, auto-bind dead UI controls, assume a resource budget, or replace a malformed glyph with what you probably meant.

## CAGE V4

`④🧰` identifies the V4 source surface. V3 remains frozen separately. V4 names use glyph sequences, and keycap digits such as `1️⃣` are the canonical numeric notation.

## Native semantics, thin hosts

CAGE language semantics belong to CAGE: lexer/parser rules, source law, verification, legality, resource contracts, compiler/runtime behavior and scene meaning live in CAGE-native sources. Browser code may present SVG and relay input, but it is not allowed to become a second CAGE interpreter.

## Visual programs are real programs

A visual CAGE program declares a retained UI surface. Studio must display the scene emitted by the admitted running program. If source declares no UI, the program is headless and Studio shows execution status only. A source-code screenshot or fake run report is not a CAGE application.
